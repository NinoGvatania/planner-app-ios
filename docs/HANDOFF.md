# Передача контекста между сессиями

Проект начался в облачной сессии Claude Code (случайно запущенной в репозитории калькулятора `calc-pedant`;
туда ничего не записано). Всё наработанное перенесено сюда, в `planner-app-ios`.

## Что где
- `docs/PLAN.md` — план разработки: принципы, стек, модель данных, экран, жесты, парсер, этапы, открытые вопросы.
- `prototype/project/` — исходник интерактивного прототипа (формат `.dc.html` холста Claude Design):
  `Main.dc.html` — весь экран и вся логика (шаблон + класс на JavaScript), остальные файлы — сцены,
  которые импортируют `Main` с разным `scene`. `canvas.json` — раскладка холста.
  Холст: https://claude.ai/artifact/FaHx7HRgcbov9Kw9mHYFTh
- `prototype/harness/` — локальный прогон прототипа в Chromium (Playwright): 22 сценария взаимодействий
  и сканер наложений. Нужен файл `support.js` (рантайм холста, файл `artifact-type/dc-runtime.js` из артефакта),
  он не хранится в репозитории.
- `PlannerCore/` — Swift‑пакет: `QuickAddParser` (правила быстрого ввода, перенесены из `parse()` прототипа
  один в один), `DayLayout` (колонки для пересекающихся задач), `FreeSlotScheduler` (раскладка просроченных
  по свободным окнам), `ClockGrid` (минуты ↔ точки, шаг 15 минут, формат времени), `DictationSplitter`
  (деление надиктованного текста на задачи; принимает `Linguistics` — части речи от платформы),
  `SpeechCleanup` (чистка речевого мусора), `WidgetSnapshot` (снимок дня для виджета, общий для
  приложения и расширения). Тесты — таблица фраз и кейсы.
- `App/` — приложение. `Model/` — SwiftData (`PlannerTask`, `Project`, `Routine`, `SeedData`);
  `State/` — `DayMath` (даты и русские подписи), `DragState` (цель сброса и зоны через PreferenceKey),
  `HoldDragGesture` (удержание → перенос на UIKit‑распознавателе), `NotificationScheduler` (уведомления;
  заодно дёргает `CalendarSync` и `WidgetBridge`), `CalendarSync` (EventKit), `WidgetBridge`, `Streak`
  (серия дней), `RoutineManager`, `SpeechRecorder` (диктовка), `TaskExtractor` (разбор расшифровки по
  порядку: `ClaudeExtractor` по своему ключу API, `OnDeviceExtractor` — Apple Intelligence через
  FoundationModels, иначе правила), `KeychainStore` (ключ Claude в связке ключей),
  `AppleLinguistics` (NaturalLanguage: глагол или нет), `DraftTask`;
  `UI/` — `PlannerScreen` (единственный экран: период × режим, пейджер, вся оркестровка жестов),
  `PagerView` (три страницы рядом, едет за пальцем; зоны и жесты только у средней), `DayTimelineView`
  (сетка на 1 или 7 дней; `live`/`syncTick` для соседних страниц), `MonthView` (один месяц; удержание
  создаёт, чипы тянутся), `YearView`, `PeriodListView` (список за период), `MatrixView` (2×2 на экран,
  проваливание, доска целей), `ProjectsView`, `DashboardView` (Swift Charts), `BacklogDrawerView`,
  `TaskRowView` (единая строка бэклога и «Просрочено»), `TaskEditSheet`, `VoiceInputSheet`, `DraftEditSheet`, `OverdueSheet`, `SettingsSheet`, `StreakSheet`,
  `HeaderView` (`Period`, `Display`; заголовок‑меню периода, серия, кнопка режима, «…», «к сегодня»; «Просрочено» — в заголовке бэклога),
  `WeekStripView` (пейджер недель), `TaskBlockView`, `Tokens`.
- `App/QuickWidget/` — расширение‑виджет «Сегодня» (своя цель `QuickWidget` в `project.pbxproj`, читает
  `WidgetSnapshot` из контейнера группы `group.com.ninogvatania.planner`; App Groups прописаны
  в `Planner/Planner.entitlements` и `QuickWidget/QuickWidget.entitlements`).
- `docs/NIGHT-REPORT.md` — что сделано за ночь, что не проверено, утренний чек-лист.
- `CLAUDE.md` — правила проекта.

## Рабочий процесс
- Код пишется в облачной сессии Claude (там нет Xcode и Swift, компилировать негде), поэтому
  компилятор — GitHub Actions: `.github/workflows/ci.yml` гоняет тесты `PlannerCore` на Linux,
  `.github/workflows/app.yml` собирает приложение на `macos-26` (Xcode 26) при каждом пуше.
- Работа идёт в ветках, в `main` попадает только зелёное. Номер сборки (`CURRENT_PROJECT_VERSION`
  в `project.pbxproj`) повышается при каждом вливании в `main` и виден в меню вида.
- На Mac: клон лежит в `~/planner-app-cloud`; после сообщения «готово» — `git pull` и ⌘R на iPhone.
- Зоны сброса: каждый вид сообщает рамки своих зон (`.reportZone("tab-3")`, `"grid-0"`, `"allday-0"`,
  `"quad-1"`, `"project-Имя"` / `"project-"` (без проекта), `"drawer"`, `"timeline"`) в координатах `"planner"`,
  `PlannerScreen.dropTarget` выбирает цель. Жест переноса — `HoldDragGesture` (UIKit‑распознаватель
  удержания 0,3 с): он висит на строке — в сетке, секциях и в бэклоге. Ячейка `List` бэклога не
  уничтожается при сворачивании панели в начале переноса: на время переноса список держит свою высоту
  (`frozenListHeight`) и только обрезается панелью. Искать строку по рамкам нельзя: рамки ячеек `List`
  устаревают (новая строка, сдвиг панели после клавиатуры) — так новая задача не тянулась (сборка 22).
  По той же причине палец для строк List берётся у UIKit в координатах окна (`HoldDragGesture.windowOrigin`,
  `PlannerOrigin`), иначе плашка улетала вверх на высоту свернувшейся панели (сборка 24). Чтобы перенос
  не оборвался при смене дня, перетаскиваемый блок остаётся в первой колонке невидимым («фантом»).
  В матрице и проектах во время удержания поверх содержимого появляется «доска» — контейнеры‑цели
  на весь экран (`allowsHitTesting(false)`, зоны сообщает только доска); строки под ней не исчезают,
  поэтому жест живёт.
- Экран = `period` (день / неделя / месяц / год) × `display` (календарь / список / матрица / проекты /
  диаграмма). Всё листается одним `PagerView`: страницы `index-1`, `index`, `index+1` рядом,
  `offset(-width + dragX)`; номер страницы периода считается от сегодняшнего (`currentPeriodIndex`),
  смена номера сдвигает `dayOffset` на период. Соседние страницы не сообщают зон (`live == false`)
  и не ловят касания; сетки дня подравнивают прокрутку под общий `GridScroll.offset` по `syncTick`.
  Пока задачу держат или тянут ручку (`GridScroll.interacting`), листание выключено.
  Сетка дня и недели — позиционные страницы (`keyed: false`): средняя позиция живёт, пока задачу
  переносят через «пружину» вкладки; остальные режимы — страницы по номеру (`keyed: true`, `ForEach`),
  уходящая страница сохраняет прокрутку и свёрнутые секции. Свайп стартует от точки, где признан
  горизонтальным (`PagerMotion.startX`), вертикальная прокрутка страниц на время свайпа выключена;
  ниже `minVisibleHeight` (неделя 93, месяц 167, матрица 102, иначе 60) страница не рисуется.
  Касания внутри страниц — только `onPageTap` / кнопки `.buttonStyle(.pageTap)`, не `Button` и не голый
  `onTapGesture`: кнопка срабатывает, когда палец отпустили над ней (а страница едет вместе с пальцем),
  тап SwiftUI срывается лишь после ~45 pt, а страница листается уже от броска в 14 pt. `onPageTap`
  спрашивает пейджер (`\.pagerMotion`, `PagerMotion.swallowsTap`), не хвост ли это свайпа (сборки 24–25).
  Вкладки дней (полоска, заголовки недели, клетки месяца) сообщают зоны только пока тянут задачу,
  а зоны сетки («timeline», «allday-…») молчат, пока страницу листают (`\.pagerSwiping`); `viewport`
  сетки следит только за вертикалью. Иначе рамки менялись бы на каждом кадре свайпа и перерисовывали
  весь экран. Если задачу взяли вторым пальцем посреди свайпа, `dragChanged` берёт верх сетки
  из `GridScroll.viewportMinY` (последнее значение зоны, его пишет экран) — самой зоны в этот кадр нет.
  Развёрнутость строки «весь день» хранится у экрана по дням страницы (`allDayExpandedDays`), строка
  устроена одинаково в обоих состояниях — фишка не пересоздаётся посреди переноса.
- Тост висит оверлеем на панели бэклога (`toastLayer`): над её верхом, а если места нет — над строкой
  ввода; место выбирается по высоте плашки при показе и не меняется, пока тост гаснет.
- Клавиатура уменьшает экран только при фокусе в строке ввода бэклога (`inputFocused`); алерты и листы
  экран под собой не сжимают.
- Из месяца тап по дню открывает день, из года тап по месяцу — месяц, из недели тап по заголовку — день;
  кнопки «назад» нет, период всегда выбирается заголовком‑меню.
  Установка на телефон без Mac невозможна (подпись); полностью без Mac — только Xcode Cloud + TestFlight
  при платном аккаунте разработчика.
- Прототип — эталон жестов и парсера; новые виды (неделя сеткой, месяц, диктовка) сделаны сразу в Swift
  по описанию в `docs/PLAN.md`.

## Решения по итогам ревью прототипа (не пересматривать без причины)
- Перетаскивание на тач‑экране только после удержания ~0,3 с; свайп по задаче = прокрутка.
- Квадрант — отдельное поле задачи, цвет выводится из него.
- Сетка дня 0:00–24:00, экран открывается на текущем часе.
- Захваченная точка блока сохраняется при переносе; шаг 15 минут; конец дня «24:00».
- Заголовки нигде не режутся молча: перенос на 2 строки + многоточие.
- Все цели нажатия ≥ 44 pt, текст ≥ 11 pt.
- Сделанная задача в бэклоге остаётся видна зачёркнутой (пока включено «показывать выполненные»).
- Рутины не попадают в «Просрочено» и в матрицу.
- Серый — «не разобрано» (квадрант 0), зелёный — «не важно, не срочно»; в матрице всё цветное.
