# Передача контекста в новый проект

Этот набор файлов — всё, что наработано по планировщику в облачной сессии Claude Code
(она была случайно запущена в репозитории калькулятора `calc-pedant`; в сам репозиторий ничего не записано).

## Что здесь
- `docs/PLAN.md` — план разработки: принципы, стек, модель данных, экран, жесты, парсер, этапы, открытые вопросы.
- `prototype/project/` — исходник интерактивного прототипа (формат `.dc.html` холста Claude Design):
  `Main.dc.html` — весь экран и вся логика (шаблон + класс на JavaScript), остальные файлы — сцены,
  которые импортируют `Main` с разным `scene`. `canvas.json` — раскладка холста.
- `prototype/harness/` — локальный прогон прототипа в Chromium (Playwright): `run.js` — 22 сценария
  взаимодействий + сканер наложений, `serve.js` — статический сервер, `review-context.md` — требования
  и описание сцен для ревью. Для запуска нужен файл `support.js` (рантайм холста) рядом с `.dc.html` —
  он не включён, его можно скачать из артефакта (файл `artifact-type/dc-runtime.js`).
- `CLAUDE.md` — заготовка правил проекта для Claude Code.

## Как продолжить в новой сессии (десктоп, своя папка)
1. Открыть папку проекта в приложении Claude (Claude Code) и начать сессию.
2. Первым сообщением: «Прочитай docs/HANDOFF.md и docs/PLAN.md, прототип в prototype/project/Main.dc.html,
   ссылка на холст в HANDOFF.md». Этого достаточно, чтобы продолжить без истории чата.
3. Если нужен новый вид или фишка — сначала правится прототип (Main.dc.html) и публикуется на тот же холст,
   потом переносится в Swift.

## Решения, принятые по итогам ревью прототипа (не пересматривать без причины)
- Перетаскивание на тач‑экране только после удержания ~0,3 с; свайп по задаче = прокрутка.
- Квадрант — отдельное поле задачи, цвет выводится из него.
- Сетка дня 0:00–24:00, экран открывается на текущем часе.
- Захваченная точка блока сохраняется при переносе; шаг 15 минут; конец дня «24:00».
- Заголовки нигде не режутся молча: перенос на 2 строки + многоточие.
- Все цели нажатия ≥ 44 pt, текст ≥ 11 pt.
- Сделанная задача в бэклоге остаётся видна зачёркнутой (пока включено «показывать выполненные»).
- Рутины не попадают в «Просрочено» и в матрицу.
